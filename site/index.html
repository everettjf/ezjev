Calibrated typed decisions from a 4B model一个 4B 模型，给出校准过的决策概率

ezjev reads a piece of state — an email, a contract, a ticket, a tool list — and answers choice, noul and score questions with a probability for every option. One prefill, no generated tokens, served through the Jev-style /v1/systemone API. ezjev 读入一段状态（邮件、合同、工单、工具列表……），回答 choice、noul、score 三类问题，给每个选项一个概率。只做一次 prefill，不生成文字，接口是 Jev 风格的 /v1/systemone。

Three question types三类问题

Every question comes back as a probability distribution over its options, so you can set thresholds, route on confidence, or abstain.每个问题返回的都是选项上的概率分布，可以按置信度设阈值、分流，或者选择不回答。

choice

Pick one option多选一

Routing, intent, tool selection, policy outcomes. Named options with descriptions; up to hundreds of options.路由、意图识别、工具选择、政策判定。选项带名称和说明，最多可以有几百个。

noul

Is it true?是否成立

Returns P(true): phishing or not, supported by the evidence or not, did the answer meet every requirement.返回 P(true)：是不是钓鱼邮件、证据是否支持、回答是否满足了所有要求。

score

Ordinal scale有序打分

Severity, urgency, quality — a distribution over ordered levels, not just a single number.严重程度、紧急程度、质量——给出各个等级上的分布，而不只是一个数字。

Quickstart快速上手

About 10 minutes from a fresh GPU machine to your first decision. Two processes run side by side: vLLM loads the model and computes option logprobs, and llm2jev turns them into the /v1/systemone API your code calls.从一台新的 GPU 机器到拿到第一个决策结果，大约 10 分钟。需要同时运行两个进程：vLLM 加载模型、计算各选项的 logprob；llm2jev 把结果包装成 /v1/systemone 接口，供你的代码调用。

You need准备

  • Linux + one NVIDIA GPU with ≥ 24 GB (weights are 9.1 GB in BF16)Linux + 一张 24 GB 以上显存的 NVIDIA GPU（BF16 权重 9.1 GB）
  • Python 3.10+ and a recent CUDA driverPython 3.10+ 和较新的 CUDA 驱动
  • ~12 GB of disk for the weights约 12 GB 磁盘空间放权重

You get得到

  • An HTTP endpoint on port 8080一个监听 8080 端口的 HTTP 接口
  • Many questions per request, each answered with per-option probabilities一次请求可以问多个问题，每个问题返回各选项的概率
  • ~34 ms per decision, no generated tokens每次决策约 34 毫秒，不生成文字

Which model?用哪个模型

  • ezjev-4b-s3, temperature 1.34: use this oneezjev-4b-s3，温度 1.34：一般用这个
  • ezjev-4b-s2, temperature 1.26: to reproduce the Decision Index runezjev-4b-s2，温度 1.26：复现 Decision Index 成绩时用

Start vLLM (terminal 1)启动 vLLM（终端 1）

The first start downloads the weights from Hugging Face (9.1 GB). Leave it running.第一次启动会从 Hugging Face 下载权重（9.1 GB）。启动后让它一直运行。

shell
vllm serve everettjf/ezjev-4b-s3 --port 8000 \
  --max-logprobs 256 --return-tokens-as-token-ids --max-model-len 32768

Ready when curl -s localhost:8000/health returns HTTP 200. --max-logprobs and --return-tokens-as-token-ids are required — without them every request fails.就绪的标志：curl -s localhost:8000/health 返回 HTTP 200。--max-logprobs 和 --return-tokens-as-token-ids 两个参数必须加，否则每个请求都会失败。

Start the decision API (terminal 2)启动决策接口（终端 2）

--model must match the model vLLM serves; --temperature must match the model (1.34 for s3).--model 要和 vLLM 加载的模型一致；--temperature 要和模型对应（s3 用 1.34）。

shell

  --url http://127.0.0.1:8000 --port 8080 --prompt chat --temperature 1.34

Ready when curl -s localhost:8080/health returns {"status": "ok", ...}.就绪的标志：curl -s localhost:8080/health 返回 {"status": "ok", ...}。

Ask questions提问

Send a state (any text, or a JSON object) and one or more named questions. Write criteria as short, mutually exclusive descriptions — they are what the model chooses between.发送一段 state（任意文字，也可以是 JSON 对象），加上一个或多个带名字的问题。criteria 写成简短、互斥的描述——模型就是在这些描述之间做选择。

curl
curl -s http://127.0.0.1:8080/v1/systemone -d '{
  "state": "I was charged twice. Please refund the duplicate.",
  "questions": {
    "refund": {"type": "noul",
               "instructions": "Does the user request a refund?"},
    "dept": {"type": "choice", "instructions": "Which department?",
             "criteria": {"billing": "Payments and refunds",
                          "technical": "Software bugs"}}
  }
}'
python
import requests

API = "http://127.0.0.1:8080/v1/systemone"
r = requests.post(API, json={
    "state": "Order 1182 arrived with a cracked screen.",
    "questions": {
        "urgency": {"type": "score",
                    "instructions": "How urgent is this?",
                    "criteria": ["routine", "soon", "urgent"]},
        "replace": {"type": "noul",
                    "instructions": "Is a refund or replacement due?"},
    },
}, timeout=30)
r.raise_for_status()
a = r.json()["answers"]
print(a["urgency"]["probabilities"])   # {"0": .., "1": .., "2": ..}
print(a["replace"]["noul"])            # P(true)

Using the probabilities: act automatically above a threshold (e.g. 0.9) and send the rest to a human or a bigger model. On the 231 JevBench public items, s3 was ≥ 0.9 confident on 132 of them and got 97% of those right (all 93 answers at ≥ 0.95 were right).怎么用这些概率：高于某个阈值（比如 0.9）就自动处理，其余交给人工或更大的模型。在 JevBench 公开题上，s3 在 231 道 JevBench 公开题里，有 132 道的置信度 ≥ 0.9，其中 97% 答对；置信度 ≥ 0.95 的 93 道全部答对。

Troubleshooting常见问题

  • 422 / 400 on every request → vLLM was started without --max-logprobs 256 --return-tokens-as-token-ids.每个请求都返回 422 / 400 → 启动 vLLM 时漏了 --max-logprobs 256 --return-tokens-as-token-ids。
  • vLLM fails compiling a kernel (no nvcc, e.g. slim containers) → add VLLM_USE_FLASHINFER_SAMPLER=0 and --additional-config '{"gdn_prefill_backend": "triton"}'. Neither changes the logprobs.vLLM 编译 kernel 失败（没有 nvcc，比如精简容器）→ 加上 VLLM_USE_FLASHINFER_SAMPLER=0 和 --additional-config '{"gdn_prefill_backend": "triton"}'，两者都不影响 logprob。
  • Out of memory → lower --max-model-len (e.g. 16384) or add --gpu-memory-utilization 0.85.显存不够 → 调小 --max-model-len（比如 16384），或加 --gpu-memory-utilization 0.85。
  • Different name in vLLM (local path or --served-model-name) → pass the same name to llm2jev with --served-model-name.vLLM 里的模型名不同（用了本地路径或 --served-model-name）→ 给 llm2jev 也传同样的 --served-model-name。

How it works工作原理

No special head and no generation. The question and all options go into one chat prompt; the model reads the logits of the option letters right after Answer:.没有特殊结构，也不生成文字。问题和所有选项放进同一个对话提示词，模型在 Answer: 之后读出各个选项字母的 logit。

Training训练

LoRA r=16 on every linear layer, including Qwen3.5's Gated-DeltaNet linear attention, merged into full weights.LoRA rank 16，覆盖所有线性层，包括 Qwen3.5 的 Gated-DeltaNet 线性注意力层，训完合并成完整权重。

Loss损失函数

Cross-entropy + Brier over the option letters only — the same prompt as inference.只看选项字母的 logit：交叉熵加 Brier。训练和推理用同一套提示词。

Calibration校准

One global temperature fitted on a held-out dev split after training (1.34 for s3).训练后在留出的开发集上拟合一个全局温度（s3 是 1.34）。

Training data训练数据

Three stages, all reproducible from the repository on Hugging Face Jobs.一共三个阶段，都能用代码仓库在 Hugging Face Jobs 上复现。

stage 1 · v2

Coverage覆盖题型

~85k samples / 106k questions from the train splits of public datasets, matched to Decision Index task formats (ContractNLI, RAGTruth, ToolACE/Glaive, When2Call, ESCI, SGD …) plus code-generated BBH / CRUXEval / GSM8K-style items.约 8.5 万条样本、10.6 万个问题，来自公开数据集的 train 部分，按 Decision Index 的题型格式整理（ContractNLI、RAGTruth、ToolACE/Glaive、When2Call、ESCI、SGD……），另加代码生成的 BBH / CRUXEval / GSM8K 风格题。

stage 2 · s2

Weak spots补弱项

Low-LR pass on weak tasks (RAGTruth, ESCI, CRUXEval, MMLU, SATA, NLI4CT) plus new phishing-email and claim-verification data, with 40% replay.用较低学习率针对弱项再训一轮（RAGTruth、ESCI、CRUXEval、MMLU、SATA、NLI4CT），另加新写的钓鱼邮件和说法核查数据，40% 回放。

stage 3 · s3

Long documents & dates长文档与日期

~20k code-generated decisions: multi-clause policies with amendments, business-day / time-zone / leap-year deadlines, pro-rating, alias → record → rule lookups, answer judging, “cannot determine” cases. Gold labels are computed by code.约 2 万道代码生成的决策题：带修订条款的多条件政策、营业日 / 时区 / 闰年期限、按比例计算、别名 → 主数据 → 规则的多跳查表、答案评判、“无法判断”的情况。答案都由程序算出。

Decontamination去重

  • Only train / dev splits are used; every row is checked against the full Decision Index suite (exact sentences + 13-gram overlap) and overlapping rows are dropped.只用 train / dev 部分；每条训练样本都和完整的 Decision Index 评测集比对（整句相同 + 13-gram 重合），重合的整条删掉。
  • No JevBench item — public or sealed — was used for training or checkpoint selection; the public items are used only for the self-test.训练和挑选模型都没用过任何 JevBench 题目（公开题和封存题都没有），公开题只用来自测。

Limits & licence局限与授权

  • Weakest on knowledge-heavy tasks (GPQA, MuSR) and on multi-step date/number arithmetic inside long documents — a single forward pass can only do so much.最弱的是依赖知识的题（GPQA、MuSR），以及长文档里需要多步计算的日期和数字题——只做一次前向计算，能力有限。
  • The Qwen base is Apache-2.0, but some training sources are non-commercial (e.g. ANLI, CC BY-NC 4.0) and some have no stated licence: treat the weights as research / non-commercial unless you have checked them.Qwen 底座是 Apache-2.0，但部分训练数据是非商用授权（例如 ANLI 是 CC BY-NC 4.0），有些没有写明授权。在核对清楚之前，请把权重当作仅供研究和非商用。
